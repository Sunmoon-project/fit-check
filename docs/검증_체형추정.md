# 체형 추정 검증

## 현재 상태

**아직 실제 데이터로 측정하지 않았어요.** 이 문서에는 실제로 측정한 오차 수치가 없어요.

스크립트를 만들 때 쓴 환경은 외부 네트워크(DNS)가 막혀 있어서 사이즈코리아(한국인 인체치수조사) 사이트에 접속하지 못했어요. 그래서 데이터를 받는 방법, 파일 형식, 실제 컬럼 이름, 이용 조건(라이선스)은 확인하지 못했어요. `--demo` 옵션으로 합성 표본을 돌려 스크립트가 끝까지 도는지만 확인했어요. 합성 표본의 출력 수치는 실제 정확도가 아니에요.

따라서 `src/lib/bodyEstimate.js` 주석의 "±3~5cm" 오차 주장은 아직 검증되지 않았어요.

## 목적

키·몸무게만으로 신체 치수를 추정하는 선형식(`estimateBody`)이 실제 실측값과 얼마나 다른지 부위·성별별로 재 보는 거예요. 대상 부위는 어깨너비, 가슴둘레, 허리둘레, 엉덩이둘레, 허벅지둘레, 팔길이, 발길이예요.

## 사용자가 할 일

1. 사이즈코리아 등에서 실측 데이터를 직접 내려받으세요. 이 저장소는 원본 데이터를 담지 않아요. 접근 방법(회원가입, 신청 여부)은 확인하지 못했어요.
2. 내려받기 전에 이용 조건(라이선스, 재배포·상업적 이용 제한)을 직접 확인하세요. 확인하지 못했어요.
3. 파일을 `data/` 또는 `.cache/`에 두세요. 두 폴더와 `validation-output/`은 `.gitignore`에 들어 있어요(핏 데이터셋 검증과 공용).
4. 컬럼 이름과 단위를 확인하고, 다르면 매핑 JSON을 만드세요(아래 참고).
5. 실행하세요.

```
npm run validate:body -- data/파일이름.csv
BODY_DATASET_PATH=data/파일이름.csv npm run validate:body
npm run validate:body -- data/파일이름.csv --map data/map.json --unit mm
npm run validate:body -- data/파일이름.csv --fit --out validation-output/body.json
npm run validate:body -- --demo
```

데이터 경로 없이 실행하면 사용법 안내만 나오고 끝나요.

## 입력 형식과 컬럼 매핑

CSV(첫 줄 헤더), JSON 배열, JSON lines를 읽어요. 사람 한 명이 한 행이어야 해요. 기본으로 아래 이름을 순서대로 찾아요. 이 이름들은 추측이에요(실제 파일은 확인하지 못했어요).

| 내부 필드 | 기본 후보 컬럼 이름 |
|---|---|
| gender | `gender`, `sex`, `성별` |
| height | `height`, `키`, `신장` |
| weight | `weight`, `몸무게`, `체중` |
| shoulder | `shoulder`, `어깨너비`, `어깨` |
| chest | `chest`, `가슴둘레`, `가슴` |
| waist | `waist`, `허리둘레`, `허리` |
| hip | `hip`, `엉덩이둘레`, `엉덩이` |
| thigh | `thigh`, `허벅지둘레`, `허벅지` |
| arm | `arm`, `팔길이`, `팔` |
| footLength | `footLength`, `foot`, `발길이`, `발` |

실제 컬럼 이름이 다르면 `--map`으로 매핑 JSON을 주세요. 내부 필드 이름을 키로, 컬럼 이름(문자열 또는 배열)을 값으로 쓰면 기본 후보보다 먼저 찾아요.

```json
{ "gender": "SEX", "height": "신장_mm", "waist": ["허리둘레_mm"] }
```

- 성별 값은 `여`/`남`, `여자`/`남자`, `female`/`male`, `f`/`m`, `2`/`1`을 알아봐요. `1`=남, `2`=여는 흔한 코딩이지만 실제 파일로 확인하지 못했으니 직접 확인하세요. 다르면 파일의 값을 바꿔 주세요.
- 길이 단위는 기본 cm이고 `--unit mm`이면 키와 모든 길이 컬럼을 mm로 읽어요. 몸무게는 항상 kg이에요. 컬럼마다 단위가 섞여 있으면 먼저 통일하세요.
- 성별·키·몸무게가 없거나, 키 120~220cm 또는 몸무게 30~200kg 밖이거나, 실측 부위가 하나도 없는 행은 제외하고 사유별 개수를 출력해요.

## 지표 정의

오차는 `추정 - 실측`이고, 모든 부위를 cm로 통일해요(`estimateBody`의 발길이는 mm라서 cm로 환산해 비교해요). 성별·부위별로 따로 계산해요.

- **표본 수**: 그 부위의 실측값이 있는 사람 수
- **MAE**: 오차 절댓값의 평균
- **RMSE**: 오차 제곱 평균의 제곱근. 큰 오차에 더 민감해요
- **bias**: 오차의 평균. +이면 과대 추정, -이면 과소 추정
- **±3cm 이내, ±5cm 이내**: 오차 절댓값이 3cm(5cm) 이하인 비율

주석의 "±3~5cm"가 맞는지 보려면 ±3cm 이내와 ±5cm 이내 비율을 보세요. 주석은 "대략 그 정도"라는 뜻이라 몇 % 이상이어야 맞다는 기준이 따로 없어요. 기준은 직접 정해야 해요.

## 계수 제안(--fit)

`--fit`을 주면 성별·부위별로 `값 ≈ 키×a + 몸무게×b + c`의 최소제곱 회귀 계수를 출력해요. **제안만 하고** `bodyEstimate.js`는 바꾸지 않아요. 계수는 이 데이터로 충분히 검증한 뒤 사람이 판단해서 옮기세요. 표본이 4개 미만이거나 키·몸무게가 한 값뿐이면 "표본 부족"으로 나와요. 현재 식에는 일부 부위의 상수항이나 `h`, `w` 항이 없는 것도 있어서, 회귀 계수와 직접 대응하지 않을 수 있어요.

## 한계

- 조사 연도와 표본 대표성: 조사 시점의 연령·지역 구성에 따라 요즘 사용자와 다를 수 있어요. 조사 대상 연령 범위도 확인하지 못했어요.
- 키·몸무게만으로는 같은 키·몸무게라도 체형 차이가 커서 오차가 줄어드는 한계가 있어요. 이건 식을 고쳐도 한계가 남아요.
- `SHAPE_ADJUST`(어깨·복부·하체 체형 보정)와 평소 사이즈 보정(`usual`)은 이 데이터로 검증할 수 없어요. 데이터에 체형 자가 응답이나 평소 사이즈가 없기 때문이에요.
- 측정 방법(주요 둘레의 측정 위치, 옷 착용 여부)이 앱에서 안내하는 방법과 다르면 편향이 생길 수 있어요.
- 이 스크립트는 오차를 재기만 해요. 오차가 크더라도 앱 동작은 바뀌지 않아요.
