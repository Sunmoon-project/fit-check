# 사진 역검색 (미검증)

중고 판매글 사진으로 같은 상품(브랜드·모델명) 후보를 찾는 기능이에요. **네트워크가 막힌 환경에서 만들어서 실제 검색 서비스를 한 번도 호출하지 못했어요.** 아래 공급자 요청·응답 모양, 인증 방식, 가격, 무료 한도, 제공 여부는 모두 공개 문서를 기억해 쓴 **추정**이에요. 키를 넣기 전에 공식 문서로 확인해야 해요. 테스트는 가짜 fetch와 가짜 응답으로만 했어요.

## 구성

| 파일 | 역할 |
|---|---|
| `server/imageSearch.js` | 공급자 어댑터 모음(레지스트리), 사진 주소 검증, 호출·타임아웃·오류 정리, 결과 캐시, 응답 정리 |
| `server/api.js` | `POST /api/image-search { imageUrl }`, `GET /api/status`의 `imageSearch`(켜짐 여부만) |
| `src/lib/imageSearch.js` | 웹 앱 클라이언트: `createServerImageProvider()`, `fetchImageSearchEnabled()` |
| `src/components/UsedListing.jsx` | 웹 `중고 상품 분석` 화면의 고지·동의·`사진으로 찾기` 버튼과 결과 |

## 켜는 방법 (서버 `.env`)

```
IMAGE_SEARCH_PROVIDER=google-vision
IMAGE_SEARCH_API_KEY=발급받은-키
```

- 둘 중 하나라도 없거나 공급자 이름을 모르면 **꺼져 있어요**. `/api/status`는 `imageSearch: false`를 주고 화면은 버튼을 비활성으로 두고 안내를 보여줘요.
- 키는 서버에서만 읽어요. 브라우저로 보내지 않고, 응답·오류 문구·로그에 넣지 않아요(테스트로 확인). 공급자 이름도 `/api/status`에 싣지 않아요.
- 웹 서버(`npm run dev`/`preview`)로 열었을 때만 켜져요. `build:file`로 만든 단일 파일은 서버가 없어 꺼져 있어요.

## 공급자 어댑터 (교체 가능)

어댑터는 `{ name, buildRequest({ imageUrl, apiKey }) → { url, init }, parseResponse(json) → { candidates, pages } }`예요. `IMAGE_SEARCH_PROVIDERS`에 이름으로 넣으면 `IMAGE_SEARCH_PROVIDER`로 고를 수 있어요.

현재 있는 것은 **Google Cloud Vision Web Detection** 하나이고, 아래는 전부 **미검증 추정**이에요.

- `POST https://vision.googleapis.com/v1/images:annotate`, 본문 `requests[0].image.source.imageUri`, `features[0].type = WEB_DETECTION`.
- 응답에서 `bestGuessLabels`, `webEntities`(설명·점수), `pagesWithMatchingImages`(주소·제목)를 읽어요.
- 인증은 키가 주소에 남지 않도록 `X-Goog-Api-Key` 헤더로 썼어요. 이 API가 그 헤더를 받는지 확인하지 못했어요. 안 받으면 `buildRequest`만 고치면 돼요.
- 가격, 무료 한도, 이미지 주소 방식(imageUri)이 이 사진 호스트에서 통하는지(일부 사이트는 외부 서버의 접근을 막아요)도 확인하지 못했어요.

## 안전 장치

- **사용자가 눌렀을 때만 호출**: 화면에서 `판매글 사진 주소가 외부 이미지 검색 서비스로 전송돼요.` 고지를 보고 체크한 뒤 `사진으로 찾기`를 눌러야 해요. `분석하기`는 검색을 부르지 않고, 앱이 열릴 때는 켜짐 여부(`/api/status`)만 물어요. 사진은 한 장만 보내요.
- **사진 주소 검증**: https만, 사용자정보(`user:pw@`)·기본 이외의 포트·`localhost`/`.local`/`.internal`·사설/루프백/링크로컬 IP(IPv4-mapped IPv6 포함)는 외부로 보내기 전에 400으로 거부해요. 이름 풀이와 사설 대역 검사는 `server/safeFetch.js`의 `assertPublicUrl`을 그대로 써요(알려진 한계인 DNS 리바인딩은 그대로예요).
- **응답은 믿지 않는 입력**: 후보 8개·링크 8개 이하, 후보 글 120자·링크 제목 160자 이하, 태그와 제어문자 제거, 링크는 https만(사용자정보 포함 주소 제외). 응답 크기는 1MB 이하예요.
- **캐시와 한도**: 같은 사진 주소는 6시간 동안 최대 200개까지 기억해 다시 부르지 않아요(실패는 기억하지 않아요). 서버 전체로 분당 20회를 넘으면 429로 막아요. 숫자는 설계상의 판단이에요.
- **오류 문구**: 잘못된 주소 400, 설정 없음 503, 한도 429, 인증/외부 오류 502, 시간 초과 504를 사용자 친화 문구로 돌려줘요. 공급자의 오류 문구는 그대로 쓰지 않아요.

## 결과를 쓰는 방식

- 후보의 브랜드·모델명은 **사이즈표 모음 DB 검색(`findChartMatches`)과 브랜드 지역 기본값의 입력**으로만 써요. 결과에 `사진 검색 후보로 찾음`이 표시돼요.
- **결과 페이지를 가져와 사이즈표를 긁는 기능은 넣지 않았어요.** 약관 문제로 대량 크롤링을 하지 않기로 했어요. `pages`는 사용자가 직접 열어보게 `target="_blank" rel="noopener noreferrer"` 링크로만 보여줘요.
- 후보는 추정이에요. 잘못 찾을 수 있고, 정확도는 측정하지 못했어요.

## 확장 프로그램에서는

확장은 **네트워크를 호출하지 않는** 원칙이라 역검색을 직접 부르지 않아요. 판단 근거는 세 가지예요. ① 키를 가진 서버가 필요하고 확장 파일에는 키를 둘 수 없어요. ② 사진 주소가 외부로 나가는 일은 동의 화면이 있는 곳에서만 하는 게 안전해요. ③ 확장은 `host_permissions`를 늘리지 않으려고 해요. 그래서 **권장안은 웹 앱에서만 제공**이고, 중고 결과 카드에는 웹 앱 `중고 상품 분석`으로 가는 링크만 넣었어요(링크는 웹 앱 첫 화면으로 열려요).

## 확인하지 못한 것

- 실제 API 호출 성공 여부, 응답 모양, 인증 헤더, 가격·한도.
- 실제 중고 사이트 사진으로 같은 상품을 찾는 정확도.
- 공개 배포 시 접속 주소 고정(DNS 리바인딩), 사용자별 호출 한도(지금은 서버 전체 한도뿐).
