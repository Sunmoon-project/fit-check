# 중고 판매글: 라벨 글자 인식과 사진 역검색 (자리만 있음)

**실제 글자 인식(OCR)은 구현하지 않았어요.** 인터페이스와 비활성 자리만 있어요. 사진 역검색은 서버 어댑터를 붙였지만 실제 API로는 확인하지 못했어요([docs/사진_역검색.md](사진_역검색.md), 미검증). 클라이언트 기본값은 `null`이라 서버 설정이 없으면 꺼져 있어요.

## 라벨/택 사진 글자 인식 — `src/lib/labelOcr.js`

- `createLabelReader(provider)`는 `{ enabled, read(source) }`를 돌려줘요. provider가 없으면 `read()`는 `{ status: 'disabled' }`만 돌려줘요.
- provider 계약: `textFromImage(source) → Promise<string>`. 읽은 글은 판매글 파서(`parseListingText`)로 사이즈·품번·브랜드만 뽑아요. 글은 2000자로 자르고 저장하지 않아요.
- 검토할 방향(이번엔 미구현): 네트워크가 되는 환경에서 [tesseract](https://github.com/tesseract-ocr/tesseract) 같은 오픈소스 OCR을 서버 쪽에 붙이거나, 브라우저용 WASM 빌드를 검토해요. 한글·영문 택 글자 인식률, 번들 크기(확장 용량), 사진이 외부로 나가는지(개인정보)를 먼저 확인해야 하고, 지금은 어느 것도 확인하지 못했어요. 확장은 네트워크를 쓰지 않는 원칙이라 확장에 직접 넣으려면 WASM을 확장 파일에 포함해야 해요.

## 사진 역검색 — `src/lib/imageSearch.js` (서버 연결은 [사진_역검색.md](사진_역검색.md) 참고)

- `createImageSearcher(provider)`는 `{ enabled, search(urls) }`를 돌려줘요. provider가 없으면 `{ status: 'disabled' }`예요.
- provider 계약: `searchByImage({ urls }) → Promise<[{ brand, model, code }]>`. https 사진 주소 최대 5개만 넘기고, 돌려받은 후보는 최대 5개, 글자 수를 제한해서 정리해요.
- 후보는 `findChartMatches(db, query, candidates)`에 넘기면 사이즈표 모음 DB 검색에 같이 쓰이고, 결과에 `사진 검색 후보로 찾음`이 표시돼요. (가짜 공급자로만 테스트했어요.)
- 웹 `중고 상품 분석` 화면에 사진 주소 입력이 있고, 서버가 켜져 있을 때만 동의 체크와 `사진으로 찾기` 버튼이 켜져요. 꺼져 있으면 `준비 중` 안내가 보여요. 확장(content script)은 직접 호출하지 않아요.

## 확인하지 못한 것

- 번개장터·후르츠패밀리 실제 페이지 구조. 도메인과 읽기 규칙은 추정이에요.
- 어떤 OCR·검색 공급자의 정확도. 아직 하나도 붙이지 않았어요.
