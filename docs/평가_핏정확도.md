# 핏 정확도 평가 (`npm run eval:fit`)

> **실제 데이터로 측정한 수치는 아직 없어요.** 이 문서와 스크립트는 "어떻게 잴 것인가"를 정해 둔 것이고, 어떤 숫자도 실제 후기로 잰 값이 아니에요. `--demo`가 보여 주는 숫자는 코드가 직접 만든 합성 데이터에서 나온 것이라 **합성 데이터, 실제 정확도 아님**이에요.

## 성공 기준 (사용자 확정)

1. **‘확신 높음’ 판정의 적중률 90~95% 이상**
2. **적용 범위**(전체 중 ‘확신 높음’을 준 비율)를 **함께 공개**: 적중률만 높이려고 쉬운 경우에만 확신 높음을 주면 범위가 줄어들어요.
3. **추천 사이즈 ±1 사이즈 적중률 90% 이상**
4. 그리고 **‘항상 맞음(정사이즈)이라고 답하는 기준선’** 과 비교

## 사용법

```bash
npm run eval:fit -- --file <평가데이터.json>      # 실제 데이터 평가
npm run eval:fit -- --demo                         # 합성 데이터로 파이프라인만 확인 (실제 정확도 아님)
npm run eval:fit                                   # 데이터가 없으면 "실제 데이터가 없어 측정하지 않았어요" 출력 후 종료
```

옵션: `--folds 5`(묶음 수) · `--seed 20240601`(분할 시드) · `--by review|product`(후기 단위 또는 상품 단위로 떼어 두기) · `--margin 2`(‘확신 높음’ 여유 기준, cm)

## 입력 데이터 스키마

### A. 후기 단위 (권장: 키·몸무게가 있어서 전체 지표를 잴 수 있어요)

```json
{
  "schemaVersion": 1,
  "kind": "fit-eval-reviews",
  "products": [
    {
      "category": "top",
      "brand": "브랜드명(선택)",
      "url": "상품 주소(선택, 지역 추정에만 써요)",
      "sizeChart": { "measures": { "S": { "shoulder": 44, "chest": 100, "arm": 60 }, "M": { "shoulder": 46, "chest": 106, "arm": 61.5 } } },
      "reviews": [
        { "size": "M", "fit": "true", "height": 175, "weight": 70, "gender": "male" }
      ]
    }
  ]
}
```

- `category`: `top` · `bottom` · `outer` · `dress` (신발은 평가하지 않아요)
- `sizeChart.measures`: 사이즈 이름 → 부위별 실측(cm, 둘레는 단면×2). 부위 이름은 `shoulder` `chest` `waist` `hip` `thigh` `arm` (기장은 판정에 쓰지 않아요). 사이즈 순서는 `rows`(있으면) → `measures` 키 순서예요.
- `reviews[]`: `fit`은 `small`(작음) · `true`(맞음) · `large`(큼). `height`(cm)·`weight`(kg)·`gender`(`male`/`female`)·`size`가 모두 있어야 평가에 쓰고, 하나라도 없으면 평가하지 않은 후기로 세요. 사이즈표에 없는 사이즈의 후기도 뺍니다.
- 공개 데이터셋(예: Rent the Runway, ModCloth 계열)은 직접 이 모양으로 변환해서 `data/` 같은 폴더에 두고 쓰세요(데이터는 저장소에 넣지 않았어요). 공개 데이터셋에는 상품별 실측이 없는 경우가 많은데, 그러면 이 평가를 쓸 수 없고 `npm run validate:fit`(이웃 투표 검증)만 가능해요.
- 파일에 `"synthetic": true`가 있으면 보고서 위·아래에 합성 표시가 붙어요.

### B. 학습 샘플 내보내기 파일 (여유분 기반)

웹 결과 화면의 **학습 샘플 내보내기(JSON)** 로 내려받은 파일이에요.

```json
{ "kind": "fitcheck-learn-samples", "schemaVersion": 1, "count": 2,
  "samples": [ { "cat": "top", "brand": "musinsa.com", "region": "kr", "label": "true", "w": 1, "e": { "chest": 12.5, "shoulder": 3 }, "d": 20000 } ] }
```

- 개인정보가 없는 허용 목록 필드만 담겨요: 종류·브랜드 키·지역 추정·라벨·가중치·부위별 여유분·날짜. 키·몸무게·성별·사이즈 이름·후기 글·닉네임·사진·상품 주소·상품명·중복 방지 id는 **내보내지 않아요**(테스트로 확인).
- 키·몸무게·사이즈 이름이 없으므로 **여유분 기반 평가**로 분기해요. 라벨 예측(확신 높음 적중률·범위·정확도·혼동행렬)만 재고, **추천 사이즈 ±1은 재지 못해요**(출력에 한계를 적어요). 이 한계 때문에 이 경로로는 목표 판정이 최대 `판정 보류`예요.
- **확장 내보내기는 추후**예요. 확장(`content.js`)에는 아직 내보내기 버튼이 없어서, 확장에 쌓인 샘플은 지금은 이 평가에 쓸 수 없어요.

## 측정 방법

1. 평가할 수 있는 후기(위 조건을 모두 만족)를 모아요.
2. **시드 고정 k-fold**(기본 5-fold, 시드 20240601)로 후기를 나눠요. 후기 하나는 정확히 한 묶음에만 들어가고, 묶음 크기 차이는 1건 이하예요. `--by product`이면 상품 단위로 나눠서 같은 상품의 후기가 학습과 평가에 섞이지 않아요(처음 보는 상품에 대한 정확도에 더 가까워요).
3. 묶음 하나를 떼어 두고, **나머지 후기만으로** 학습 샘플을 만들어 학습값 묶음(`trainModel`)을 구성해요.
4. 떼어 둔 후기마다 **작성자의 키·몸무게·성별**로 신체 치수를 추정하고 **구매 사이즈**의 실측과 비교해 부위별 여유분을 구한 뒤 핏 라벨을 예측해요.
   - 학습값의 부위 기준(`snug`, `relaxed`)과 브랜드/지역 오프셋을 써서, 한 부위라도 `snug` 미만이면 `small`, 모든 부위가 `relaxed` 이상이면 `large`, 아니면 `true`예요(어깨·가슴·허리·엉덩이·허벅지·소매. 기장·신발은 제외).
   - **‘확신 높음’** = 비교 부위가 2개 이상이고, 예측을 뒤집으려면 필요한 여유분(경계까지 거리)이 2cm 이상일 때. 이 값은 설계상의 판단이에요(`--margin`으로 바꿔 볼 수 있어요).
5. 실제 라벨과 비교해 지표를 계산해요.

### 지표

| 지표 | 뜻 |
| --- | --- |
| ‘확신 높음’ 적중률 | 확신 높음 판정만 모아서 실제 라벨과 같았던 비율 |
| 적용 범위 | 전체 중 확신 높음을 준 비율. 적중률과 반드시 같이 읽어요 |
| 전체 정확도, 혼동행렬, 라벨별 precision/recall | 모든 후기 기준 |
| 추천 사이즈 ±1 적중률 | ‘맞음(true)’ 후기의 **구매 사이즈를 정답**으로 보고, 같은 체형으로 추천한 사이즈가 정답 사이즈의 ±1칸 안인 비율. 사이즈가 4개 미만인 상품은 ±1이 거의 항상 맞아서 뺍니다 |
| ‘항상 정사이즈’ 기준선 | 항상 `true`라고 답했을 때의 전체 정확도와, 같은 확신 높음 부분집합에서의 적중률. 사이즈는 ‘사이즈표 가운데 사이즈 항상 추천’이 기준선이에요 |
| 학습값 없는 현재 규칙 | 같은 판정을 학습값 없이 기본 기준(`EASE_RULES`)으로만 한 결과. 학습값이 도움이 되는지 비교해요 |
| Wilson 95% 구간 | 모든 비율 옆에 표본이 적어서 생기는 불확실성을 같이 보여줘요 |

### 목표 판정

- `목표 달성`: ‘확신 높음’ 적중률 ≥ 90%, ±1 적중률 ≥ 90%, 전체 정확도와 확신 높음 적중률이 모두 ‘항상 정사이즈’ 기준선보다 높음. 점추정으로 비교하고, Wilson 구간 하한이 목표 아래면 그 사실을 같이 적어요. 95% 이상인지도 표시해요.
- `목표 미달`: 하나라도 기준을 못 넘음.
- `판정 보류`: 후기가 50건 미만이거나, 확신 높음 판정이 30건 미만이거나, ±1 평가가 30건 미만이거나, ±1을 잴 수 없는 입력일 때. 이때는 합격·불합격을 말하지 않아요.
- `--demo`나 `synthetic` 표시가 있는 파일이면 판정 문구에도 “합성 데이터 기준이며 실제 달성이 아님”을 붙여요.

## 한계 (꼭 읽어 주세요)

- **라벨 잡음**: 후기의 ‘작아요/커요’는 사람이 쓴 주관적 평가예요. 같은 옷도 취향·착용 습관·세탁에 따라 라벨이 달라서, 정답 자체에 잡음이 있어요. 이 잡음이 많으면 어떤 모델도 90%에 닿기 어렵고, 못 닿은 것이 모델 탓인지 라벨 탓인지 이 평가만으로는 구분할 수 없어요.
- **표본 수**: 표본이 적으면 수치가 크게 흔들려요. 그래서 구간을 같이 보여주고 표본이 기준 미만이면 `판정 보류`로 둬요. 또 목표가 90%인데 확신 높음 판정이 30건이면 구간 폭이 ±10%p 가까이 돼요. 합격선은 점추정 기준이지만 구간 하한도 같이 봐 주세요.
- **편향**: 후기를 쓰는 사람은 전체 구매자가 아니에요(극단적으로 만족하거나 불만인 사람, 사진 후기 작성자, 특정 체형이 많이 쏠림). 라벨이 `true`에 쏠린 데이터라면 ‘항상 정사이즈’ 기준선이 이미 높아서 정확도만으로는 판단하기 어려워요(기준선이 60% 이상이면 경고를 출력해요). 반품한 사람은 후기를 안 남길 수 있어요(생존 편향). 한 데이터셋·한 쇼핑몰에서 잰 값을 다른 곳에 그대로 적용할 수 없어요.
- **누수**: 후기 단위로 나누면 같은 상품의 다른 후기가 학습에 들어가서, 처음 보는 상품에 대한 정확도보다 낙관적일 수 있어요. 처음 보는 상품 기준은 `--by product`로 확인하세요. 학습 샘플 평가(B)는 상품 구분이 없어서 항상 낙관적일 수 있어요.
- **학습 샘플 상한**: 학습 샘플 변환은 상품당 60건까지만 만들어서, 후기가 아주 많은 상품은 일부만 학습에 써요. 후기 이상치 제외도 학습 쪽에만 적용하고, 떼어 둔 후기에는 적용하지 않아요.
- **키·몸무게 → 체형 추정 오차**: 작성자의 신체 치수는 키·몸무게로 추정한 값이에요(`validate:body`로도 아직 실측 검증 전). 이 오차가 라벨 예측 오차에 섞여 들어가요.
- **합성 데이터**: `--demo`의 데이터는 시드 고정으로 코드가 만든 것이에요. 파이프라인이 끝까지 도는지 확인하는 용도이고 합성 방식에 따라 결과가 달라지므로, 그 수치를 정확도로 인용하면 안 돼요.
- **판단으로 정한 값**: ‘확신 높음’의 2cm 여유, 비교 부위 2개, 표본 부족 기준(50/30/30건)은 설계상의 판단이고 어떤 실제 데이터로 정한 값이 아니에요.
- **사이즈 ±1**: 정답으로 쓰는 ‘맞음’ 후기의 구매 사이즈도 그 사람의 취향에 따라 고른 것이라, 한 체형에 정답 사이즈가 하나인 것은 아니에요. 그래서 ±1칸을 허용해요.
