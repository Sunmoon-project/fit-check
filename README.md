## 🎯 무엇을 푸나요

온라인으로 옷을 살 때 가장 자주 겪는 문제는 **"이 옷, 나한테 맞을까?"** 입니다.
사이즈표의 숫자는 어렵고, 후기는 나와 체형이 다른 사람 이야기라 믿기 어렵고, 안 맞으면 반품하는 수고와 배송비가 듭니다.

핏체크는 이 문제를 세 가지 근거로 좁혀줍니다.

- **내 체형 ↔ 상품 실측의 차이**로 부위별 핏(타이트 / 적당 / 넉넉)을 계산합니다.
- **나와 키·몸무게가 비슷한 사람의 후기**를 먼저 보여줍니다.
- **내 사진 위에 옷을 얹은 미리보기**로 대략적인 모습을 확인합니다.

쇼핑몰마다 흩어진 사이즈 판단을 **상품 링크 하나로** 끝내는 것이 목표입니다.

## ✨ 주요 기능

| 기능 | 설명 |
| --- | --- |
| 🧍 **체형 온보딩** | 성별, 키, 몸무게, 어깨·배·하체 체형, 평소 입는 사이즈를 한 단계씩 입력해요. 치수를 직접 적으면 추정값 대신 그 값을 써요. |
| 🔗 **상품 링크 분석** | 쇼핑몰 상품 주소를 붙여넣으면 서버가 페이지를 받아 상품명, 가격, 이미지, 사이즈표, 리뷰를 뽑아요. EUC-KR로 된 오래된 쇼핑몰 페이지도 읽어요. |
| 📏 **사이즈·핏 추천** | 사이즈표 실측과 내 치수의 차이(여유분)로 부위별 핏을 판정하고 추천 사이즈를 골라요. |
| 💬 **비슷한 체형 리뷰** | 리뷰에 적힌 키·몸무게·구매 사이즈를 읽어 나와 비슷한 사람의 후기를 먼저 보여줘요. 결과 화면의 `체형 비교`에서 성별·키·몸무게를 내 값과 나란히 볼 수 있어요. |
| 🖼️ **사진 합성 미리보기** | 내 전신 사진 위에 배경을 지운 옷 이미지를 얹어 대략적인 모습을 보여줘요. 선택한 사이즈가 넉넉할수록 조금 크게 그려요. |
| 🤖 **AI 합성** | Hugging Face의 무료 IDM-VTON Space로 실제 착용 이미지를 만들어요. 키 없이 바로 동작해요(상의·아우터). |
| 🗂️ **옷장** | 마음에 든 옷을 사이즈·핏 판정·합성 이미지와 함께 담고, 나란히 비교하거나 비슷한 옷과 치수 차이를 볼 수 있어요. |
| 🎯 **착용 후기 보정** | 산 옷이 작았는지, 컸는지 기록하면 다음 추천부터 부위별로 보정해요. |

## 🧭 사용 흐름

```
① 내 정보 입력  →  ② 상품 링크 붙여넣기  →  ③ 사이즈·핏 추천 + 리뷰
                                                  ↓
                               ④ 사진 합성 미리보기 / AI 합성  →  ⑤ 옷장에 담기
```

> 💡 상품 링크가 없어도 괜찮아요. 링크 입력 화면의 **데모 상품으로 체험하기**에서 모든 기능을 바로 써볼 수 있어요.

## 🚀 시작하기

Node.js 18 이상이 필요해요.

```bash
npm install
npm run dev      # http://localhost:5173
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 + API (`/api/*`) 실행 |
| `npm run build` | 화면 파일만 빌드 (`dist/`) |
| `npm run build:file` | 서버 없이 여는 HTML 파일 하나 빌드 (`dist/fit-check.html`) |
| `npm run preview` | 빌드 결과를 API와 함께 실행 |
| `npm run smoke` | 추천 로직·파서·보안 검사 스모크 테스트 |

> ⚠️ API(`/api/status`, `/api/product`, `/api/tryon`)는 Vite 개발·미리보기 서버에 붙는 플러그인이에요.
> `dist/` 폴더만 정적 호스팅에 올리면 **상품 링크 분석과 AI 합성이 동작하지 않아요.** `npm run preview`로 실행하거나 별도 서버가 필요해요.

### 서버 없이 파일 하나로 보기

```bash
npm run build:file   # dist/fit-check.html 생성
```

`dist/fit-check.html`을 더블클릭하면 브라우저에서 바로 열려요. JS·CSS가 모두 파일 안에 들어 있어서 다른 파일이 필요 없어요.
온보딩, 데모 상품 사이즈·핏 추천과 리뷰, 사진 합성 미리보기, 옷장은 동작해요. 상품 링크 분석과 AI 합성은 서버가 필요해서 이 파일에서는 꺼져 있어요.
`npm run build`를 다시 돌리면 `dist/`가 비워지니 그 뒤에 `npm run build:file`을 다시 실행하세요.

### 지금 하는 일 (기반 다지기)

- **성능 최적화** — 배경 제거·이미지 합성 등 무거운 연산을 다듬어 반응을 빠르게.
- **디자인 개편** — 실제 쇼핑몰(무신사·29CM 류)에서 쓰는 것처럼 익숙한 커머스 UI로 전환. 반응형으로 데스크톱·모바일 모두 지원.

### 다음 단계 (정확도·디자인이 안정되면)

| 기능 | 왜 하나요 |
| --- | --- |
| ✅ 🧩 **크롬 확장 프로그램** (초안, 실제 Chrome 미검증) | 링크를 복사해서 붙여넣는 한 단계를 없애요. 쇼핑몰 상품 페이지에서 바로 "내 사이즈 찾기"가 떠요. 자바스크립트로 그리는 쇼핑몰(무신사 등)도 페이지 안에서 직접 데이터를 읽어 분석 한계를 줄여요. |
| 📊 **반품 절감 대시보드 (B2B)** | 브랜드·쇼핑몰이 "사이즈 추천으로 반품이 얼마나 줄었는지"를 보는 화면. 소비자 앱을 넘어 수익 모델이 분명한 B2B로 확장하는 축이에요. |
| ✅ 🔎 **추천 신뢰도 표시** (완료) | "리뷰 12건 기준, 확신도 높음"처럼 추천의 근거와 확신도를 함께 보여줘요. 틀릴 수 있는 추천을 정직하게 드러내 신뢰를 쌓아요. 확신도는 후기·사이즈표 근거를 규칙으로 나눈 구분이며, 보정된 확률이 아니고 정확도는 아직 측정하지 않았어요. |
| ✅ 🧹 **후기 이상치 자동 제외** (구현, 가짜 데이터 테스트만) | 불가능한 값(키 140~210cm·몸무게 35~150kg·BMI 14~40 밖), 모순(한 후기에 작아요·커요 동시, 구매 사이즈가 상품에 없음), 같은 사이즈 후기 5건 이상일 때 부위별 여유분이 중앙값 ± 3×MAD 밖인 후기를 추천·유사도 계산에서 빼요. 비슷한 체형·같은 사이즈 다수와 평가가 반대인 후기는 제외하지 않고 가중치만 줄여요. 제외한 후기는 숨기지 않고 `제외됨(사유)`로 웹 리뷰 영역과 확장 전체 리뷰 탭에 보여주고, 진단 리포트에는 사유별 건수만 담아요. 기준값은 설계상의 판단이고 실제 후기로 정확도를 재지 않았어요. |
| ✅ 🎓 **후기 학습 코어** (구현, 가짜 데이터 테스트만) | 상품을 분석할 때 후기에서 학습 샘플(종류·브랜드·부위별 여유분·핏 라벨·가중치)을 이 브라우저에 쌓고(같은 후기는 한 번만, 제외된 후기는 쓰지 않고 가중치 낮춘 후기는 그 가중치로), 라벨별 여유분의 중앙값 사이 중간점으로 종류별 여유분 기준을 보정해요. 기존 기준(`EASE_RULES`)을 사전값으로 두고 표본이 적으면 그대로 유지해요(라벨당 3건 미만이면 추정 안 함, 표본이 늘수록 최대 ±5cm까지만 이동). 브랜드는 같은 여유분에서 라벨이 쏠리는 정도를 cm 오프셋으로 보되 표본 수로 축소해요(3건 미만은 0, 최대 ±4cm). 결과 화면에 `학습값 사용 중(샘플 N건)`과 `학습값 초기화` 버튼이 있어요. 학습값 묶음은 스키마 버전을 가지고, 브라우저에서 만들었든 나중에 서버에서 만들었든 같은 코드로 읽어요(서버 업로드는 아직 없어요). 기준값은 설계상의 판단이고, 학습값이 판정을 더 정확하게 만드는지는 검증하지 않았어요. |
| ✅ 🗂 **사이즈표 모음 DB** (구현, 가짜 데이터 테스트만) | 분석한 상품의 사이즈표를 브랜드·품번·모델명·카테고리·대상 성별과 함께 이 브라우저에 저장하고 `search({brand, model, code, category, gender})`로 점수순 후보(점수·근거 포함)를 찾아요. 글자는 대소문자·공백·특수문자를 정규화하고 브랜드는 한글/영문 별칭(나이키↔nike 등 일부 목록)을 같은 키로 봐요. 품번이 정확히 같으면 90점 이상, 모델명은 토큰 겹침과 편집거리로 비슷한 정도를 점수화하며 카테고리·성별이 다르면 감점해요. 같은 상품(주소, 또는 브랜드+품번)은 갱신하고, 300건·약 500KB를 넘으면 오래된 항목부터 정리해요. 확장은 사이즈표를 읽은 상품만 자동 저장하고, 웹에서는 상단 `사이즈표` 버튼에서 목록·검색·비우기를 해요. `createSizeChartDb(adapter)`의 어댑터만 바꾸면 서버 DB로 옮길 수 있게 만들었지만 서버 업로드는 구현하지 않았어요. 점수 규칙은 설계상의 판단이고 실제 상품으로 정확도를 재지 않았어요. 다음 단계(중고 판매글 분석)에서 브랜드·모델명으로 사이즈표를 찾는 입력으로 쓸 예정이에요. |
| ✅ 🌏 **브랜드 지역 사전 보정 + 자세한 근거** (구현, 가짜 데이터 테스트만) | 브랜드 지역(국내/일본/미국/유럽/기타/알 수 없음)을 쇼핑몰 표시·브랜드 사전·사이즈 표기(US/EU/UK/JP)·통화·도메인 근거 점수를 합산해 **추정**하고(근거가 없거나 동점이면 `알 수 없음`), 결과 화면에 `브랜드 지역: 일본(추정) 근거: …`로 보여줘요. 같은 지역 브랜드들의 후기로 모은 **지역별 오프셋**이 학습값에 있으면(지역 표본 5건 이상, 표본이 적을수록 0 쪽으로 축소, 최대 ±3cm) 브랜드 값이 없는 상품에 쓰고, 없으면 보정 0이에요(브랜드와 지역 값을 더하지 않아요). 사이즈표·후기·판매글 실측이 모두 없을 때만 사이즈 표기(국내 남성 상의 95/100/105 가슴둘레 호칭, 하의 인치, 신발 mm 등)의 뜻을 `근사/출처 확인 필요` 플래그와 함께 참고로 보여줘요(추천 계산에는 쓰지 않아요, 출처 확인 목록은 `docs/사이즈체계_출처확인.md`). 추천 결과에는 후기 몇 건 중 제외 몇 건, 학습값 사용 여부와 샘플 수, 브랜드/지역 보정 크기, 부위별 여유분 판정 줄이 붙어요. 지역별 사이즈 차이는 **검증 전 가설**이라 고정 수치를 넣지 않았어요. |
| 🔗 **공유 링크** | "이 옷 나한테 맞을까?"를 친구에게 바로 보내는 기능. 비용 없이 사용자를 늘리는 성장 축이에요. |

> 추천 신뢰도·반품 대시보드·공유 링크·크롬 확장이 같은 후기 스키마를 쓰도록 설계했어요. [docs/후기데이터_설계.md](docs/후기데이터_설계.md)

## 🧩 크롬 확장

상품 페이지에서 바로 "내 사이즈 찾기"를 눌러 추천을 받는 Manifest V3 확장이에요. 열려 있는 페이지의 DOM에서 사이즈표와 리뷰를 직접 읽어서, 자바스크립트로 그리는 쇼핑몰도 대상으로 해요. 추천과 확신도·근거 문장은 웹 앱과 같은 핏 엔진(`src/lib/fitEngine.js`)을 써요.

설치(개발자 모드):

1. `npm run build:extension` → `dist-extension/` 생성
2. 크롬에서 `chrome://extensions` → 우측 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → `dist-extension` 폴더 선택
4. 확장 아이콘을 눌러 키·몸무게 등을 저장하고, 상품 페이지에서 **내 사이즈 찾기**를 눌러요.

- 무신사·29CM·W컨셉 페이지에는 버튼이 자동으로 뜨고, 다른 사이트는 아이콘을 누른 탭에서만(activeTab) 실행돼요.
- 사이즈표도 리뷰도 거의 못 읽으면 추천하지 않고 그렇게 알려줘요.
- **리뷰 탭**: 결과 카드의 리뷰 원문 구역에 `비슷한 체형` / `전체 리뷰` / `사진 모아보기` / `체형 비교` 탭이 있어요. 리뷰 글과 사진을 세로로 스크롤하며 볼 수 있고, 탭은 방향키로도 옮겨요.
- **체형 비교 탭**: 리뷰 최대 20건의 성별·키·몸무게를 내 값과 막대로 나란히 보여주고, 유사도 숫자가 탭을 처음 열 때 0에서 올라가요. 시스템의 `움직임 줄이기` 설정이면 애니메이션 없이 바로 최종 값을 보여줘요. 웹 결과 화면에도 같은 `내 체형과 비교하기` 구역이 있고, 두 곳의 유사도 숫자는 같은 함수(`src/lib/similarityBreakdown.js`)에서 나와요. 가짜 데이터와 가짜 DOM으로만 시험했고 실제 무신사나 크롬에서 확인하지 못했어요.
- **체형 비교 표시**: 후기마다 키·몸무게를 ‘나 / 후기’ 두 칸으로 묶어 한 번에 보여주고, 그 아래 ‘비슷한 체형’ 퍼센트 막대 하나를 둬요. 막대 색은 구간별(비슷함 초록, 조금 달라요 주황, 많이 달라요 회색)이고, 구간 기준은 아래 `BODY_SIM.threshold`(비슷함)와 그 절반(조금 달라요)이에요. 확장 카드와 웹 결과 화면 모두 같은 함수(`similarityTier`, `diffText`)를 써요. 웹 카드는 종류별(추천/부위별 핏/후기/사이즈표/체형 비교/합성/후기 남기기)로 색 띠와 제목 색이 달라요.
- **신발 사이즈**: 실측 제목이 없어도 `사이즈(mm) 230 240 250`처럼 220~310 사이로 커지는 숫자 사이즈를 발길이(mm)로 읽어요(신발로 보일 때만). 구매 옵션이 `블랙 / 250`처럼 mm 숫자뿐이면 옵션에서 사이즈 목록을 만들어요. 리뷰의 `265mm 구매`, `270 신어요`, `구매옵션 화이트 / 255`도 읽고, `평소 250 신는데` 같은 평소 사이즈는 제외해요. 가짜 표·가짜 문장으로만 확인했고 실제 무신사 신발 페이지에서는 확인하지 못했어요.
- **사이즈표 읽기 보강**: 옵션이 `블랙 / M`, `블랙 / 0 (S)`처럼 색상과 함께 읽혀도 표와 이어지고, 영문 헤더(`Size | Length | Chest`)와 `발 길이`처럼 띄어 쓴 헤더도 읽어요.
- **상품 페이지가 아닐 때**: 장바구니·목록처럼 상품 정보도 사이즈표도 없는 화면에서 눌렀다면 ‘상품 상세 페이지가 아니에요’ 안내를 먼저 보여줘요(상품 페이지인데 못 읽은 경우를 위해 직접 입력 양식은 그대로 남겨요). 크롬 내부 페이지처럼 확장을 넣을 수 없는 곳은 팝업이 따로 안내해요.
- **비슷한 체형 기준**: 후기와 내 체형의 거리는 `키 차이 x 0.8 + 몸무게 차이 x 1.6`이고, 유사도는 `100 - 거리 x 2.5`예요. 65점 이상이면 비슷한 체형으로 묶어요. 성별이 다르면 0점이라 제외되고, 후기 성별을 못 읽으면 10점을 깎아요(내 프로필에 성별이 없으면 성별은 따지지 않아요). 이 숫자들은 설계상의 판단이고 실제 후기 데이터로 정확도를 재서 정한 값이 아니에요. 값은 `src/lib/fitEngine.js`의 `BODY_SIM` 한 곳에 있고, 성별은 무신사 후기의 `남성 · 170cm · 70kg` 같은 체형 줄 형식을 가정해 읽는데 실제 사이트에서 확인하지 못했어요.
- **내 옷장으로 보내기 (자동 전달)**: 카드의 버튼을 누르면 그때만 추천 사이즈·부위별 판정·리뷰(닉네임, 원문, 사진 주소)가 웹 옷장 형식으로 변환돼 확장 저장소(`chrome.storage.local`)의 대기열에 들어가요. 핏체크 웹이 열려 있으면 바로, 닫혀 있으면 다음에 열 때 **붙여넣기 없이 내 옷장에 자동으로 담기고** ‘확장에서 N벌 가져왔어요’ 알림이 떠요. 서버를 거치지 않고 이 브라우저 안에서만 옮겨요. 내 체형 정보(키·몸무게 등)는 담지 않아요(리뷰 작성자의 키·몸무게는 리뷰 정보로 들어가요).
  - 동작 방식: 웹 앱 주소에서만 도는 브리지(`extension/bridge.js`)가 대기열을 `window.postMessage`로 웹 앱에 전달하고, 웹 앱이 검사해 저장한 뒤 처리한 항목 id를 돌려주면(ack) 대기열에서 지워요. 같은 항목이 두 번 전달돼도 id 기준으로 한 번만 저장하고, 대기열은 최대 10개·3일이 지나면 버려요. 웹 페이지가 브리지에 시킬 수 있는 일은 ‘대기열 다시 받기’와 ‘처리한 id 알리기’뿐이에요. 받은 데이터는 믿지 않고 붙여넣기와 같은 검사(형식·길이·개수, `http`/`https` 주소만)를 다시 거쳐요.
  - 자동 전달이 되는 웹 앱 주소: `npm run dev`(`http://localhost:5173`), `npm run preview`(`http://localhost:4173`), 각각 `127.0.0.1` 주소, 그리고 `npm run build:file`로 만든 `fit-check.html`을 `file://`로 연 경우예요. **`file://`로 쓰려면** `chrome://extensions` → 핏체크 → 세부정보에서 **‘파일 URL에 대한 액세스 허용’**을 켜야 해요(크롬 정책이라 확장이 대신 켤 수 없어요). `file://` 페이지의 origin은 `null`이라 출처 대신 ‘같은 창에서 온 메시지인지’와 데이터 검사로 막아요.
  - **배포 주소를 추가하려면**: `src/lib/wardrobeSync.js`의 `WEB_APP_ORIGINS`에 `https://내-주소`를 더하고, `extension/manifest.json`의 브리지 `matches`에 `https://내-주소/*`를 더한 뒤 `npm run build:extension`으로 다시 빌드하세요(smoke가 두 목록이 같은지 확인해요). 추가 권한(`tabs` 등)과 백그라운드 스크립트는 쓰지 않아서, 웹이 닫혀 있으면 자동으로 탭을 열지 않고 카드의 ‘핏체크 웹 열기’ 링크만 보여줘요.
  - 자동 전달이 안 될 때: 카드의 **붙여넣기용으로 복사** 후 웹 앱의 **내 옷장 > 확장에서 직접 가져오기**에 붙여넣거나 파일로 골라도 돼요.
  - 가짜 HTML·가짜 데이터·가짜 window와 chrome.storage로만 테스트했고, 실제 무신사와 실제 크롬에서는 확인하지 못했어요.

사이즈 측정이 안 될 때:

1. 코드를 받았다면 `npm run build:extension`으로 다시 빌드해요.
2. `chrome://extensions`에서 이 확장의 **새로고침**(↻)을 누르고, 무신사 탭도 새로고침해요.
3. 상품 페이지의 **사이즈 정보** 영역이 접혀 있으면 펼쳐서 페이지에 나타나게 한 뒤, **내 사이즈 찾기**를 다시 눌러요. 이미지로만 된 사이즈표는 읽을 수 없어요.
4. 그래도 안 되면 결과 카드의 **진단 리포트 복사**를 눌러 나온 글을 개발자에게 보내 주세요.
5. 진단 리포트가 도움이 안 되면 **사이즈표 직접 입력**으로 상의·하의 치수(cm)를 넣어 분석할 수 있어요. 입력값은 저장하지 않고 이번 분석에만 써요.

사이즈 이름이 이상하거나(예: 무신사 옵션은 `0 (S)`, `1 (M)`인데 엉뚱한 숫자가 나옴) 리뷰가 너무 적게 잡힐 때 다시 확인하는 순서:

1. `npm run build:extension`으로 다시 빌드해요.
2. `chrome://extensions`에서 이 확장의 **새로고침**(↻)을 누르고, 무신사 탭도 새로고침해요.
3. 결과 카드의 **리뷰 더 불러오기**를 눌러요(아래 설명). 직접 리뷰 영역을 스크롤해 불러온 뒤 버튼을 다시 눌러도 돼요. **내 사이즈 찾기**를 누르면 리뷰를 30건까지 자동으로 불러오고(끝나면 원래 위치로 돌아와요), 그 밖에는 스크롤하지 않고 페이지에 불러와진 리뷰만 읽어요.
4. **내 사이즈 찾기**를 눌러요. 카드의 요약에 "페이지에 불러온 리뷰 N건 기준(전체 약 M건 중 일부)"이 보이는지, 추천 사이즈 이름이 구매 옵션(`1 (M)` 등)과 같은지 확인해요. 리뷰를 더 불러온 뒤 버튼을 다시 누르면 반영돼요.
5. 틀렸거나 추천이 없으면 **진단 리포트 복사**를 눌러 아래 줄을 확인해요: 사이즈표 후보 개수·선택한 후보(table/grid/transposed), "첫 열 제목이 실측 항목이라 버린 후보", 사이즈 이름 개수·모양(paren/alpha/numeric), 구매 옵션 이름 개수와 표와 겹침 개수, 불러온 리뷰 수와 페이지에 표시된 전체 리뷰 수.

동작 규칙(코드로 반영한 것):

- 사이즈 이름은 `0 (S)`·`1(M)`·`4 (2XL)`, `S/M/L`, `95/100/105`, `FREE`를 받아요. 화면에는 페이지 원문 표기(`1 (M)`)로 보여줘요.
- 표의 첫 열 제목이 `총장`·`어깨` 같은 실측 항목이면 가로세로가 뒤바뀐 후보로 보고 버려요. 숫자뿐인 이름은 2개 이상이고 증가 순서일 때만 받고, 글자/괄호 이름보다 후순위예요.
- 페이지에서 `N (S)` 모양의 구매 옵션 이름을 읽을 수 있으면, 옵션과 하나도 겹치지 않는 사이즈표는 버려요. 추천 사이즈는 사이즈표(없으면 구매 옵션)에 있는 이름만 나와요.

**리뷰 더 불러오기 (선택 기능)**

- 위치: 결과 카드의 리뷰 안내 위쪽에 있는 **리뷰 더 불러오기** 버튼이에요. 진단 리포트 복사 버튼은 카드 맨 아래에 있고, 추천이 나온(ok) 결과에도 항상 붙어요.
- **내 사이즈 찾기**를 누르면 화면의 리뷰가 30건보다 적을 때 30건까지 자동으로 불러온 뒤 분석해요. 진행 중에는 `불러온 리뷰 N건`과 **중단** 버튼이 보여요.
- **리뷰 더 불러오기**는 누를 때마다 지금 건수 + 10건을 목표로 더 불러와요. 마지막 리뷰 쪽으로 스크롤하고(리뷰가 안쪽 스크롤 상자에 있으면 그 상자도 끝까지), 리뷰 영역 안의 `더보기`·`더 보기`·`리뷰 더보기`·`후기 더보기`·`다음`·`다음 페이지`와 바로 다음 쪽 번호 버튼만 한 단계에 최대 한 번 눌러요. 구매·장바구니·좋아요·찜·주문·결제·쿠폰·삭제·신고·작성·로그인·공유·댓글 같은 글이 들어간 버튼과 리뷰 영역 밖의 버튼은 누르지 않아요.
- 더보기 버튼이 보이지 않으면 처음 한 번만 `스냅·후기` 같은 리뷰 탭을 눌러요. 화면이 탭이라고 밝힌 요소(`role="tab"` 또는 `role="tablist"` 안)이고, 글 전체가 리뷰 탭 이름 모양이며, 아직 열리지 않았고, 다른 페이지로 가는 링크가 아닐 때만이에요.
- 한도: 목표 건수에 닿거나, 최대 15단계 또는 약 20초, 리뷰가 늘지 않는 단계가 2번 이어지면 멈춰요.
- 결과 한 줄: 늘었으면 `리뷰 N건을 더 불러왔어요(총 M건)`, 안 늘었으면 `더 불러올 리뷰가 없어요(현재 N건)` 또는 `리뷰를 더 불러오지 못했어요(현재 N건) — 리뷰 탭을 열고 다시 눌러 주세요`예요.
- 쪽 번호 방식 목록은 다음 쪽을 열면 앞 쪽 리뷰가 화면에서 사라져서 건수가 늘지 않을 수 있어요(화면에 보이는 리뷰만 읽어요).
- 멈춘 이유(진단 리포트에 `리뷰 불러오기: 전 -> 후, 멈춘 이유`로 나와요): `reached-end`(페이지에 표시된 전체 리뷰 수만큼 불러옴), `no-growth`(더 불러올 리뷰가 없어 보임), `limit`(목표 건수 또는 단계 한도), `limit-time`(시간 한도), `aborted`(중단), `not-run`(실행 안 함).
- 끝나면 시작 때의 스크롤 위치로 항상 돌아오고, 늘어난 리뷰로 다시 분석해요. 네트워크 호출과 권한 추가는 없어요.
- **실제 Chrome과 무신사 페이지에서는 확인하지 못했어요.** 쇼핑몰마다 마크업이 달라 더보기 버튼을 못 찾을 수 있고, 그 경우 스크롤만 하고 멈춰요. 단위 테스트는 판단 함수(`shouldStop`, `isSafeMoreButton`, `isReviewTab`, `loadResultText` 등)와 가짜 DOM에서 더보기를 누르면 리뷰가 늘어나는 흉내 페이지만 다뤄요.

| 쇼핑몰 내부 리뷰 API를 사용자 로그인 세션으로 호출 | 리뷰를 한 번에 많이 받을 수 있어요 | 이용약관 위반 소지, 해당 도메인 `host_permissions` 추가 필요(현재는 요청하지 않음), 개인정보·세션 취급 부담, API가 바뀌면 깨져요 |
| 사용자가 직접 리뷰 영역을 스크롤/페이지 넘김 후 버튼 다시 누르기 (기본 방식) | 권한·약관 문제가 없고 구현이 단순해요 | 사용자가 손을 써야 하고, 읽는 리뷰 수가 화면에 불러온 만큼으로 제한돼요 |
| 리뷰 속 키·몸무게·사이즈를 사용자가 직접 입력 | 정확하고 안전해요 | 번거로워서 건수가 늘기 어려워요 |

**이번 수정에서 확인하지 못한 것**

- **무신사 실제 DOM은 확인하지 못했어요.** 위 수정은 직접 만든 가짜 HTML 테스트(`가짜 HTML:`로 시작하는 테스트)로만 확인했고, 실제 무신사 검증이 아니에요.
- **큰 숫자 `67`이 어디서 나왔는지는 가설이에요.** 사이즈 이름 줄(`0 (S)` 등)을 못 알아봐서, 가로세로를 뒤집은 후보의 첫 열(`총장` 값 67, 69, 71…)이 사이즈 이름으로 읽혔을 것이라고 추정하지만 확정하지 못했어요. 새 진단 줄이 실제 페이지에서 이를 가려내는 용도예요.
- 구매 옵션 이름과 전체 리뷰 수는 `textContent`의 일반 패턴으로 읽어요. 실제 무신사 문구와 맞는지는 확인하지 못했어요. 글자 사이즈(S/M/L)만 나열된 옵션 목록은 읽지 않아요.
- 실제 Chrome에 설치해서 동작을 확인하는 것도 하지 않았어요.

진단 리포트: 클립보드에 복사만 하고 어디로도 자동 전송하지 않아요. 보낼지는 직접 정해요. 분석 단계와 결과 상태, 페이지에서 찾은 표·사이즈표 후보의 개수나 구조 같은 진단 정보를 담아요. 체형 정보(키·몸무게 등), 리뷰 본문, 로그인·개인 정보는 담지 않는 것을 목표로 했어요. 복사한 글은 보내기 전에 한 번 읽어 보세요.

개인정보:

- 체형 정보는 `chrome.storage.local`(이 브라우저)에만 저장돼요. 확장은 네트워크 호출을 하지 않고, 원격 코드를 불러오지 않아요. 모든 사이트에 대한 호스트 권한(`<all_urls>`)도 요청하지 않아요(권한: storage, activeTab, scripting). 웹 옷장 자동 전달용 브리지는 위 웹 앱 주소에서만 실행되는 content script이고 추가 권한은 없어요. ‘내 옷장으로 보내기’를 누르면 대기열(최대 10개·3일)이 `chrome.storage.local`에 잠시 남아요.
- 후기 기여 대기열은 확장에서 쓰지 않아요.

**확인하지 못한 것 (솔직하게)**

- 이 환경에서는 **실제 Chrome에 설치해 보지 못했어요.** manifest 검사, 빌드 결과 확인, 직접 만든 HTML 예시로 DOM 파서 테스트까지만 했어요(테스트는 cheerio를 DOM처럼 감싼 어댑터를 써요).
- **무신사 등 개별 쇼핑몰의 실제 페이지 구조에 맞는지는 검증하지 않았어요.** 표(`<table>`)와 class에 `review`가 들어간 요소를 찾는 일반 규칙이라, 사이즈표가 이미지이거나 리뷰가 다른 구조(또는 iframe, 더 보기 클릭 후 로드)이면 못 읽을 수 있어요. 쇼핑몰별 선택자는 실제 페이지로 확인하며 다듬어야 해요.
- **무신사 실제 DOM은 확인하지 못했어요.** 이 환경에서는 무신사에 접속할 수 없었어요. 새로 넣은 사이즈표 감지는 일반 규칙이고, 직접 만든 가짜 HTML로만 테스트했어요. 실제 무신사 페이지에서 고쳐졌는지는 검증하지 않았어요.
- **"사이즈 측정이 안 된다"는 원인은 확정하지 못했어요.** 후보는 표가 아닌 레이아웃, 접혀 있거나 늦게 불러오는 영역, 이미지 사이즈표, 페이지가 덜 그려진 시점의 분석이에요. 진단 리포트가 원인을 좁히는 용도예요.
- 추천의 정확도는 측정하지 않았어요. 화면의 확신도는 후기·사이즈표 근거의 양으로 나눈 규칙 기반 단계예요.
- 버튼은 JSON-LD Product, `og:type=product`, 사이즈표 중 하나가 있는 페이지에만 떠요. 팝업에서 직접 실행하면 어느 페이지든 실행해요.
- 리뷰 요소는 키·몸무게·사이즈·핏 단서가 하나라도 있어야 건수에 넣지만, 실제 쇼핑몰에서 오탐·누락이 얼마나 되는지는 확인하지 못했어요.
- `executeScript` 직후 메시지 전달 순서, Shadow DOM 표시는 실제 Chrome에서 수동으로 확인해야 해요(아직 안 함). `build:extension`의 네트워크 호출 검사는 정규식 기반이라 회귀 감지용이에요.

## 🤖 AI 합성 켜기

AI 합성은 Hugging Face Space [yisol/IDM-VTON](https://huggingface.co/spaces/yisol/IDM-VTON)을 **무료**로 써요.
`npm run dev`로 실행하면 키 없이 바로 결과 화면의 **AI로 합성하기** 버튼이 켜져요. 서버(`server/hfTryOn.js`)가 Gradio API로 Space를 호출하고, 결과 이미지를 받아 브라우저에 넘겨요.

- **기다리는 시간**: 무료 GPU(ZeroGPU) 대기열을 거쳐서 보통 **30초~2분** 걸려요. 서버는 최대 5분까지 기다려요. 중간에 끊겨도 Space의 작업은 취소되지 않아 GPU 사용량이 쓰이니, 다시 누르기 전에 잠시 기다려주세요.
- **하루 사용량**: 무료 GPU 시간은 하루 단위로 제한돼요(토큰 없이 약 2분). 다 쓰면 "오늘 쓸 수 있는 무료 GPU 시간을 다 썼어요" 안내가 나와요. 내일 다시 시도하거나 아래처럼 토큰을 넣어주세요.
- **같은 사진·같은 옷**으로 다시 누르면 서버에 저장해둔 결과를 바로 보여줘서 사용량을 쓰지 않아요(서버를 다시 시작하면 비워져요).
- **상의·아우터만 지원**: 무료 Space의 자동 마스크는 상반신만 칠해서, 하의·원피스·신발은 AI 합성 버튼이 꺼져 있어요(사진 미리보기는 그대로 쓸 수 있어요).
- **옷 설명**: 모델이 영어 프롬프트를 쓰기 때문에 한글 상품명 대신 `a top`, `an outer jacket` 같은 영어 문구를 보내요.
- **라이선스**: IDM-VTON 모델은 **CC BY-NC-SA 4.0**이라 **비상업적 용도로만** 쓸 수 있어요. 상업 서비스로 전환할 때는 FASHN 등 상업용 API로 교체가 필요해요.

## 🔒 개인정보와 보안

- 체형 정보, 사진, 옷장은 **이 브라우저(localStorage)에 저장**되고 서버에 따로 보관하지 않아요.
- **익명 통계 기여 동의(선택, 기본 해제)**: 체크하면 구간화된 익명 레코드가 이 브라우저의 대기열에만 쌓여요. **서버 저장소는 아직 없어서 실제로 전송되지 않아요.** 허용 목록에 있는 대형 쇼핑몰의 기록만 쌓여요. 체크를 풀거나 동의 문구 버전이 바뀌면 대기열이 지워져요. 일정 인원 이상만 공개하는 익명 처리(k-익명)는 서버를 만들 때 적용할 계획이고 아직 적용되지 않았어요. 설계와 동의 문구는 [docs/후기데이터_설계.md](docs/후기데이터_설계.md)를 보세요(법률 자문 아님, 법무 확인 필요).
- **후기 이상치 제외**는 이 브라우저 안에서만 계산해요(서버·외부 전송 없음). 제외된 후기의 글과 키·몸무게는 진단 리포트와 익명 통계 기록에 들어가지 않고, 진단 리포트에는 사유별 건수만 담겨요(테스트로 확인).
- **후기 학습 샘플**은 이 브라우저 안에만 저장돼요. 웹 앱은 `localStorage`의 `fitcheck.learn.v1`, 크롬 확장은 `chrome.storage.local`의 같은 키에 저장하고 서버로 보내지 않아요(웹과 확장은 저장소가 서로 달라 샘플을 공유하지 않아요). 샘플에는 종류, 브랜드(알려진 쇼핑몰 도메인), 핏 라벨, 가중치, 부위별 여유분(0.5cm 단위), 날짜(일 번호), 중복 방지용 해시만 있고 닉네임·후기 본문·사진 주소·상품명·상품 주소·키·몸무게·성별·사이즈 이름은 저장하지 않아요(테스트로 확인). 키·몸무게는 기여 기록처럼 구간으로 남기지 않고 아예 버려요. 서버로 나가지 않아서 체형별 통계가 필요 없고, 여유분만 있으면 학습되기 때문이에요. 샘플은 최대 500건·약 200KB이고 넘으면 오래된 것부터 정리해요. 결과 화면의 `학습값 초기화`를 누르면 샘플과 학습값이 모두 지워져요. 스키마 버전이 다르면 저장된 값을 폐기해요.
- **사이즈표 모음**은 이 브라우저 안에만 저장돼요. 웹 앱은 `localStorage`의 `fitcheck.sizechart.v1`, 크롬 확장은 `chrome.storage.local`의 같은 키이고 서버로 보내지 않아요(웹과 확장은 저장소가 서로 달라 공유하지 않아요). 브랜드, 모델명(상품명), 품번, 카테고리, 대상 성별, 사이즈표 숫자, 상품 주소(쿼리·해시 제외), 날짜만 저장하고 내 키·몸무게·후기 본문·닉네임·사진 주소·추천 결과는 저장하지 않아요(테스트로 확인). 사이즈표를 읽지 못한 상품은 저장하지 않고, 웹의 데모 상품도 저장하지 않아요. 웹 `사이즈표` 화면과 확장 카드의 `사이즈표 모음 비우기` 버튼으로 모두 지울 수 있어요. 스키마 버전이 다르면 저장된 값을 폐기해요.
- **리뷰 닉네임·원문·사진 주소**: 확장에서 **내 옷장으로 보내기**를 누르고 웹 옷장으로 넘어온(자동 전달 또는 붙여넣기) 경우에만 이 브라우저(localStorage)에 저장돼요. 업로드하지 않고, 진단 리포트와 익명 통계 기록에는 들어가지 않아요(테스트로 확인). 사진은 저장하지 않고, 화면에 보일 때 쇼핑몰 주소에서 불러와요. 옷장의 **리뷰만 지우기**로 지울 수 있고, 저장 공간이 부족하면 오래된 항목의 이미지, 그다음 리뷰부터 빠져요.
- **예외: AI로 합성하기**를 누르면 그때만 내 전신 사진과 옷 이미지가 Hugging Face Space로 전송돼요. 버튼 아래에도 같은 안내가 나와요.
- `HF_TOKEN`은 서버(`server/api.js`)에서만 읽고 브라우저로 보내지 않아요. `.env`는 git에 올라가지 않아요.
- 상품 페이지를 가져올 때 localhost·사설 IP·클라우드 메타데이터 주소(IPv4-mapped IPv6 표기 포함)는 막아요. 리다이렉트마다 다시 검사해요.
- `/api/*` POST 요청은 `Content-Type: application/json`이고 같은 출처일 때만 받아요. 다른 사이트가 몰래 AI 합성을 호출해 함께 쓰는 무료 GPU 사용량을 써버리는 일을 막아요.

## ⚠️ 한계

- **실시간 페이지 분석**: 화면을 자바스크립트로 그리는 쇼핑몰(예: [댄블](https://danble.co.kr), 무신사)은 HTML에 리뷰나 사이즈표가 없을 때가 많아요. 리뷰는 지금 페이지에 들어 있는 구조화 데이터(JSON-LD)에서만 읽어요. 이럴 땐 결과 화면에 안내 문구가 뜨고, 데모 상품으로 기능을 체험할 수 있어요. (로드맵의 크롬 확장이 이 한계를 줄여요.)
- **배경 지우기**: 사진 모서리 색에서부터 비슷한 색을 지우는 방식이라 단색 배경에서 잘 돼요. 쇼핑몰 이미지는 CORS 설정 때문에 배경을 못 지울 수 있어서, 이때는 옷 사진을 직접 올려주세요.
- **개발용 서버**: DNS 검사와 실제 접속이 따로 이름을 풀기 때문에 DNS 리바인딩은 완전히 막지 못해요. 내 컴퓨터에서 쓰는 용도로 만들었고, 공개 배포하려면 서버를 따로 보강해야 해요.
- **정확도 미검증**: 비슷한 체형 후기 투표가 핏을 얼마나 맞히는지 재는 스크립트(`npm run validate:fit`)는 만들었지만, 실제 공개 데이터로는 아직 측정하지 않았어요. 방법은 [docs/검증_핏데이터셋.md](docs/검증_핏데이터셋.md)를 보세요.
- **체형 추정 오차 미검증**: `estimateBody`의 "±3~5cm" 주장을 실측 데이터로 재는 스크립트(`npm run validate:body`)는 만들었지만, 실제 데이터로는 아직 측정하지 않았어요. 방법은 [docs/검증_체형추정.md](docs/검증_체형추정.md)를 보세요.
- **이상치 기준 미검증**: 후기 이상치 제외의 기준값(범위, 3×MAD, 5건, 가중치 0.4 등)은 설계상의 판단이에요. 가짜 데이터로 동작만 테스트했고, 실제 후기에서 제외가 맞는지는 확인하지 않았어요. 정상 후기가 제외될 수 있어서 제외된 후기를 숨기지 않고 사유와 함께 보여줘요.
- **지역 가설 미검증**: 미국 브랜드는 같은 글자 사이즈가 국내보다 크게, 일본은 비슷하거나 약간 작게, 유럽은 슬림하게 나온다는 이야기는 검증 전 가설이에요. 코드에 고정 수치를 넣지 않았고 이 브라우저에 모은 후기에서 확인된 만큼만 반영해요. 브랜드 사전은 직접 정리한 최소 예시(전부 추정 표시)이고, 쇼핑몰의 해외 브랜드 표시는 입력으로만 받으며 실제 쇼핑몰 페이지에서 읽는지는 확인하지 못했어요. 사이즈 체계 변환표는 표준 원문을 확인하지 못한 근사값이에요. 근거 줄의 숫자는 센 값이고 정확도를 잰 값이 아니에요.
- **학습값 기준 미검증**: 학습 기준의 숫자(라벨당 최소 3건, 섞는 세기 20건, 이동 한계 ±5cm, 브랜드 축소 10건, 오프셋 한계 ±4cm)는 설계상의 판단이에요. 가짜 데이터로 동작만 테스트했고 실제 후기에서 정확도가 올라가는지는 확인하지 않았어요. 현재 상품 정보에서 브랜드 이름을 따로 읽지 않아서, 브랜드 오프셋은 알려진 쇼핑몰 도메인(예: musinsa.com) 단위로만 동작해요. 같은 상품의 후기가 자기 판정에도 다시 반영될 수 있어요.
- **추천은 참고용**이에요. 원단 신축성, 두께, 재단 차이는 반영되지 않아요.
